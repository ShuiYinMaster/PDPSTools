## 需要优先解决的问题

### P1：PS/EMS 中相同 ID 的对象被合并，单对象删除会同时修改两个条目

证据：`workers/psz_worker.py` 的 `build_snapshot()` 用 `objects.update()` 合并两个条目；`ui/psz_parser_page.py` 的 `_delete_selected()` 只把 `ext_id` 传给修复线程；`PszRepairWorker.run()` 在所有条目中按这个 ID 删除。

已用临时 PSZ 复现：PsState 和 EmsState 各放一个 `ExternalId="shared"`、名称不同的对象，执行一次按 ID 删除后，两个条目中的对象数都从 1 变成 0。界面提示包含“所属条目”，但实际删除范围不限于该条目，可能超出用户对单对象删除的预期。

建议：对象标识改为 `(entry, ext_id)`；界面明确区分“删除当前条目对象”和“跨条目联动删除”，引用清理依据各条目语义处理，预览受影响对象。

验收：相同 ID、不同条目的两个对象都能显示；删除其中一个不影响另一个；明确选择联动删除时再同时修改；重复 ID 和悬空引用检查仍正确。

### P1：PSZ 回写缺少完整事务边界

证据：`core/psz_parser.py:rebuild_zip()` 用 `shutil.copy2(tmp, src_psz)` 覆盖源包；`PszRepairWorker.run()` 对多个 XML 条目分别重建并提交，`_run_rebuild()` 在回写前没有解析校验外部 XML。

影响：覆盖期间失败可能损坏原包；第一个条目写入后第二个条目失败会留下部分修改；不合规的 XML 也可能先被写入。已有 `.bak` 能提供一定恢复能力，但不等于原子提交，而且后续操作会覆盖同名备份。此项为代码路径审查结论，未对用户文件做故障注入。

建议：一次收集全部条目变更，在同目录生成唯一临时包，完成 XML 和 ZIP 校验后用原子替换提交；增加修改前文件指纹检查和可追溯备份，失败清理临时文件并保持原包不变。

验收：两条目联动、无效 XML、提交失败、源文件外部变化均有测试；任一步骤失败时原包内容不变，备份可恢复。

### P1：关闭主窗口没有协调正在运行的后台任务

证据：`ui/main_window.py:closeEvent()` 只处理项目数据保存，随后接受关闭；项目页持有 `ScanWorker`，PSZ 页持有加载/修复 `QThread`。

影响：任务未结束时销毁窗口及其子线程存在 Qt 进程异常退出风险；PSZ 写操作还可能被中断。当前结论来自线程生命周期审查，未在真实长任务中触发崩溃。

建议：集中管理忙碌状态；读任务支持取消并在退出前等待结束；写任务进入提交阶段后等待完成再关闭；同一资源禁止重复任务进入。

验收：扫描、加载、修复过程中关闭窗口均可控，没有运行中的线程被销毁，也不留下部分写入。

### P2：扫描缓存只按路径复用，修改后的 PSZ 不会自动重新解析

证据：`workers/scan_worker.py:run()` 在路径命中 `_existing` 后直接复用记录，未比较文件大小或修改时间。

影响：同一路径的工程被替换或修改后，扫描仍展示旧元数据。

建议：记录 `mtime_ns` 与大小，变更时重新解析；保留用户手工维护的字段，提供“强制重新解析”，汇总失败项而不是静默忽略。

验收：文件内容改变后自动更新解析字段；未变文件继续复用；手工备注不丢失；单个损坏文件不阻断扫描且可查看失败原因。

### P2：新增 CATIA 写操作需要失败恢复和自动测试

证据：`core/stud_point_extractor.py:get_stud_points()` 创建 CATPart 后继续逐点写入，中途失败没有处理本次已创建的组件；再次执行又会因同名输出组件存在而停止。

建议：分离“提取点位”和“创建 CATIA 对象”；记录本次新建对象及失败阶段，提供可明确执行的清理/重试方案；抽取装配变换纯函数，并补齐模拟 COM 与现场回归样例。

验收：多层装配的旋转和平移、重复实例名、读到无效 Position、写到一半失败都有可预测结果；明确坐标系与单位。
